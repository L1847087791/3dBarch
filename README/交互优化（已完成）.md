# 交互优化（已完成）

## 优化概述

本次优化主要解决了3D场景中射线追踪交互的边界问题，提升了用户体验。优化集中在拖拽检测和鼠标离开画布的处理上。

---

## 问题分析与解决方案

### 问题1：拖拽导致的误点击

**问题描述：**
- 用户拖拽摄像机视角时（鼠标按下并移动），如果恰好在主机上松开鼠标，会触发主机的点击回调
- 这会导致摄像机执行不期望的缩放动画，降低用户体验

**问题根因：**
- 原有代码没有区分"点击"和"拖拽"操作
- `click` 事件在 `mouseup` 时无条件触发，不管鼠标在按下期间是否移动过

**优化措施：**
1. 添加拖拽检测机制：
   - 监听 `mousedown` 事件，记录鼠标按下时的位置和时间戳
   - 在 `mousemove` 中计算移动距离，超过阈值（5px）则标记为拖拽状态
   - 在 `click` 事件中判断：只有移动距离小于5px且按下时长小于200ms才视为有效点击

2. 相关代码位置：
   - 构造函数：第66-78行（拖拽状态变量）
   - `_onMouseDown` 方法：第145-157行
   - `_onMouseClick` 方法：第811-860行（添加距离和时长判断）

**优化效果：**
- ✅ 拖拽摄像机后在主机上松手，不再触发点击事件
- ✅ 用户可以自由拖拽视角，不会产生误操作

---

### 问题2：拖拽期间的副作用交互

**问题描述：**
- 用户拖拽摄像机时（鼠标按下并移动），鼠标经过主机会触发悬停效果
- 悬停效果包括：浮层显示、主机缩放
- 这些副作用会产生视觉干扰，影响拖拽体验

**问题根因：**
- `_onMouseMove` 方法始终处理悬停逻辑，没有判断是否在拖拽状态

**优化措施：**
1. 在 `_onMouseMove` 方法中添加拖拽状态检查：
   - 如果 `isDragging` 为 true，直接返回，跳过所有悬停检测

2. 相关代码位置：
   - `_onMouseMove` 方法：第167-211行（第180-182行为拖拽检查）

**优化效果：**
- ✅ 拖拽期间不会显示悬停浮层
- ✅ 拖拽期间主机不会缩放
- ✅ 拖拽体验更加流畅，无视觉干扰

---

### 问题3：鼠标离开画布时悬停状态残留

**问题描述：**
- 鼠标悬停在主机上时，会显示浮层并缩放主机
- 当鼠标移出画布区域（例如移到相邻的UI元素），悬停状态不会清除
- 导致浮层一直显示，主机保持缩放状态

**问题根因：**
- 原有代码没有监听 `mouseleave` 事件
- 鼠标离开画布时，无法触发悬停状态的清理逻辑

**优化措施：**
1. 添加 `mouseleave` 事件处理：
   - 监听画布的 `mouseleave` 事件
   - 触发时重置所有悬停状态和拖拽状态
   - 根据视图模式（METRIC/COMPONENT）清除相应的悬停效果
   - 触发相应的离开回调（`onBarLeave`、`onLayerLeave`、`onMetricLeave`）

2. 相关代码位置：
   - 构造函数：第84行（绑定 `_onMouseLeave`）
   - `_initEventListeners` 方法：第116行（添加监听）
   - `_onMouseLeave` 方法：第214-269行
   - `dispose` 方法：第1089行（移除监听）

**优化效果：**
- ✅ 鼠标移出画布时，浮层立即消失
- ✅ 鼠标移出画布时，主机缩放立即恢复
- ✅ 拖拽时移出画布，拖拽状态正确重置

---

### 问题4：摄像机动画期间浮层错位

**问题描述：**
- 点击主机触发摄像机动画时，浮层位置相对视口固定不变
- 摄像机移动后，浮层脱离主机上方，产生错位

**问题根因：**
- 点击主机时，悬停状态未清除，浮层继续显示
- 浮层位置是基于3D坐标投影到屏幕坐标计算的，摄像机移动后投影位置改变

**优化措施：**
1. 在 `_handleOuterShellClick` 方法中，点击主机前先清除浮层：
   - 触发 `onBarLeave` 回调，清除当前显示的浮层
   - 然后再触发 `onBarClick` 回调，执行点击逻辑

2. 相关代码位置：
   - `_handleOuterShellClick` 方法：第880-883行

**优化效果：**
- ✅ 点击主机时浮层立即消失
- ✅ 摄像机动画期间不会出现浮层错位问题
- ✅ 交互逻辑更加清晰

## 技术实现细节

### 拖拽检测算法

```javascript
// 1. 记录鼠标按下状态
_onMouseDown(event) {
  this.isMouseDown = true;
  this.isDragging = false;
  this.mouseDownTime = Date.now();
  this.mouseDownPosition = {
    x: event.clientX,
    y: event.clientY
  };
}

// 2. 检测拖拽
_onMouseMove(event) {
  if (this.isMouseDown && this.mouseDownPosition) {
    const deltaX = event.clientX - this.mouseDownPosition.x;
    const deltaY = event.clientY - this.mouseDownPosition.y;
    const distance = Math.sqrt(deltaX * deltaX + deltaY * deltaY);

    if (distance > this.dragThreshold) { // 5px
      this.isDragging = true;
    }
  }

  if (this.isDragging) {
    return; // 跳过悬停检测
  }
  // ... 悬停检测逻辑
}

// 3. 点击判断
_onMouseClick(event) {
  let distance = 0;
  let duration = 0;

  if (this.mouseDownPosition) {
    const deltaX = event.clientX - this.mouseDownPosition.x;
    const deltaY = event.clientY - this.mouseDownPosition.y;
    distance = Math.sqrt(deltaX * deltaX + deltaY * deltaY);
    duration = Date.now() - this.mouseDownTime;
  }

  // 重置状态
  this.isMouseDown = false;
  this.isDragging = false;
  this.mouseDownPosition = null;

  // 只有满足条件才视为有效点击
  if (distance > this.dragThreshold || duration > this.clickTimeThreshold) {
    return;
  }
  // ... 点击处理逻辑
}
```

### 状态变量说明

| 变量名 | 类型 | 说明 |
|--------|------|------|
| `isMouseDown` | boolean | 鼠标是否按下 |
| `isDragging` | boolean | 是否正在拖拽 |
| `mouseDownPosition` | Object | 鼠标按下时的位置 {x, y} |
| `mouseDownTime` | number | 鼠标按下的时间戳 |
| `dragThreshold` | number | 拖拽阈值（5像素） |
| `clickTimeThreshold` | number | 点击时间阈值（200毫秒） |

## 总结

本次优化通过添加拖拽检测机制和 `mouseleave` 事件处理，有效解决了射线追踪交互中的边界问题：

1. **拖拽检测**：区分点击和拖拽操作，避免误触发

4. **交互优化**：点击前清除浮层，避免动画期间错位

优化后的交互更加符合用户预期，提升了整体使用体验。代码改动集中在 `InteractionManager.js` 文件中，保持了良好的解耦性，不影响其他功能模块。
