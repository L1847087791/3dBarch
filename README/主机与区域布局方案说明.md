# 主机与区域布局方案说明

> **前端所需数据格式**
> ```javascript
> // 主机数据（barSceneData）
> {
>   bars: [
>     {
>       position: { x: 0, y: 0, z: 0 },   // 主机位置
>       groupName: '区域 1',               // 所属区域名称
>       height: 30,                        // 柱状图高度
>       outerColor: 'normal',              // 外层颜色：normal|active|warning|error|offline|maintenance
>       uuid: 'host-uuid-001',             // 主机唯一标识
>       layers: [                          // 内层数据
>         { color: 'normal', uuid: 'layer-uuid-001' },  // 颜色：normal|info|warning|error|critical
>         { color: 'warning', uuid: 'layer-uuid-002' }
>       ]
>     }
>   ]
> }
>
> // 区域数据（groupIndicatorInfo）
> [
>   {
>     centerX: 0,           // 区域中心X坐标
>     centerZ: 0,           // 区域中心Z坐标
>     width: 300,           // 区域宽度
>     depth: 120,           // 区域深度
>     label: '区域 1'       // 区域名称
>   }
> ]
> ```

## 一、问题背景

当前主机和区域位置由前端硬编码计算，不够灵活。需要设计一套布局方案，支持：
- 动态数量的区域和主机
- 灵活的布局配置
- 前后端职责清晰

---

## 二、方案一：后端计算位置（推荐）

### 2.1 方案说明

后端在返回数据时直接计算好每个主机和区域的位置坐标，前端只负责渲染。

### 2.2 数据接口规范

```typescript
interface SceneData {
  // 布局配置（可选，用于前端了解布局参数）
  layoutConfig?: {
    hostSpacing: number;      // 主机间距
    regionGap: number;        // 区域间隔
    barWidth: number;         // 柱状图宽度
    barHeight: number;        // 柱状图高度
  };

  // 区域列表
  regions: Region[];

  // 主机列表
  hosts: Host[];
}

interface Region {
  id: string;                 // 区域唯一标识
  name: string;               // 区域名称
  // 区域边界（用于绘制边框）
  bounds: {
    centerX: number;          // 中心X坐标
    centerZ: number;          // 中心Z坐标
    width: number;            // 宽度（X方向）
    depth: number;            // 深度（Z方向）
  };
  // 标签位置
  labelPosition: {
    x: number;
    y: number;
    z: number;
  };
}

interface Host {
  id: string;                 // 主机唯一标识
  regionId: string;           // 所属区域ID
  name?: string;              // 主机名称
  // 主机位置
  position: {
    x: number;
    y: number;
    z: number;
  };
  height: number;             // 柱状图高度
  outerColor: string;         // 外层颜色
  layers: Layer[];            // 内层数据
}

interface Layer {
  id: string;
  color: string;
}
```

### 2.3 后端布局算法建议

```python
# Python 伪代码示例

def calculate_layout(regions_data, config):
    """
    计算区域和主机的布局位置

    参数:
        regions_data: 区域数据，包含每个区域的主机列表
        config: 布局配置
    """
    host_spacing = config.get('host_spacing', 12)
    region_gap = config.get('region_gap', 300)
    bar_width = config.get('bar_width', 8)
    regions_per_row = config.get('regions_per_row', 4)
    hosts_per_row = config.get('hosts_per_row', 25)  # 每区域每行主机数

    regions = []
    hosts = []

    for region_index, region_data in enumerate(regions_data):
        # 计算区域在网格中的位置
        region_col = region_index % regions_per_row
        region_row = region_index // regions_per_row

        # 计算区域内主机布局
        host_count = len(region_data['hosts'])
        region_cols = min(host_count, hosts_per_row)
        region_rows = math.ceil(host_count / hosts_per_row)

        # 计算区域尺寸
        region_width = (region_cols - 1) * host_spacing + bar_width + 8
        region_depth = (region_rows - 1) * host_spacing + bar_width + 8

        # 计算区域起始位置（居中布局）
        total_width = calculate_total_width(...)
        region_start_x = -total_width / 2 + region_col * (max_region_width + region_gap)
        region_start_z = -total_depth / 2 + region_row * (max_region_depth + region_gap)

        # 区域中心
        center_x = region_start_x + (region_cols - 1) * host_spacing / 2
        center_z = region_start_z + (region_rows - 1) * host_spacing / 2

        regions.append({
            'id': region_data['id'],
            'name': region_data['name'],
            'bounds': {
                'centerX': center_x,
                'centerZ': center_z,
                'width': region_width,
                'depth': region_depth
            },
            'labelPosition': {
                'x': center_x,
                'y': 0,
                'z': center_z - region_depth / 2 - 30
            }
        })

        # 计算每个主机的位置
        for host_index, host_data in enumerate(region_data['hosts']):
            col = host_index % hosts_per_row
            row = host_index // hosts_per_row

            hosts.append({
                'id': host_data['id'],
                'regionId': region_data['id'],
                'position': {
                    'x': region_start_x + col * host_spacing,
                    'y': 0,
                    'z': region_start_z + row * host_spacing
                },
                'height': host_data.get('height', 30),
                'outerColor': host_data.get('status', 'normal'),
                'layers': host_data.get('layers', [])
            })

    return {'regions': regions, 'hosts': hosts}
```

### 2.4 优点

| 优点 | 说明 |
|------|------|
| 前端简单 | 只需渲染，无需计算布局 |
| 灵活性高 | 后端可实现复杂布局算法 |
| 一致性好 | 布局逻辑集中管理 |
| 可扩展 | 易于支持不同布局策略 |

### 2.5 复杂度

| 项目 | 复杂度 | 说明 |
|------|--------|------|
| 后端开发 | ⭐⭐ | 需实现布局算法 |
| 前端开发 | ⭐ | 仅需适配数据格式 |
| 联调成本 | ⭐⭐ | 需要定义接口规范 |
| 维护成本 | ⭐ | 布局逻辑集中 |

## 三、方案二：前端网格布局工具

### 3.1 方案说明

封装前端布局工具，后端只需提供分组信息（区域包含哪些主机），前端自动计算位置。

### 3.2 数据接口规范

```typescript
// 后端返回的简化数据
interface SimpleSceneData {
  regions: SimpleRegion[];
}

interface SimpleRegion {
  id: string;
  name: string;
  hosts: SimpleHost[];
}

interface SimpleHost {
  id: string;
  height?: number;
  outerColor?: string;
  layers: Layer[];
}
```

### 3.3 前端布局工具实现

```javascript
// src/utils/LayoutCalculator.js

/**
 * 网格布局计算器
 * 根据分组数据自动计算主机和区域位置
 */
class GridLayoutCalculator {
  constructor(config = {}) {
    this.config = {
      hostSpacing: config.hostSpacing || 12,      // 主机间距
      regionGap: config.regionGap || 300,         // 区域间隔
      barWidth: config.barWidth || 8,             // 柱状图宽度
      barHeight: config.barHeight || 30,          // 柱状图高度
      regionsPerRow: config.regionsPerRow || 4,   // 每行区域数
      hostsPerRow: config.hostsPerRow || 25,      // 每区域每行主机数
      padding: config.padding || 8,               // 区域边距
    };
  }

  /**
   * 计算布局
   * @param {Array} regionsData - 区域数据数组
   * @returns {Object} - { bars, groupIndicatorInfo }
   */
  calculate(regionsData) {
    const bars = [];
    const groupIndicatorInfo = [];

    const { hostSpacing, regionGap, barWidth, barHeight,
            regionsPerRow, hostsPerRow, padding } = this.config;

    // 预计算每个区域的尺寸
    const regionSizes = regionsData.map(region => {
      const hostCount = region.hosts.length;
      const cols = Math.min(hostCount, hostsPerRow);
      const rows = Math.ceil(hostCount / hostsPerRow);
      return {
        cols,
        rows,
        width: (cols - 1) * hostSpacing + padding * 2,
        depth: (rows - 1) * hostSpacing + padding * 2
      };
    });

    // 计算最大区域尺寸（用于对齐）
    const maxWidth = Math.max(...regionSizes.map(s => s.width));
    const maxDepth = Math.max(...regionSizes.map(s => s.depth));

    // 计算总布局尺寸
    const totalRegionRows = Math.ceil(regionsData.length / regionsPerRow);
    const totalWidth = regionsPerRow * maxWidth + (regionsPerRow - 1) * regionGap;
    const totalDepth = totalRegionRows * maxDepth + (totalRegionRows - 1) * regionGap;

    // 遍历每个区域
    regionsData.forEach((region, regionIndex) => {
      const regionCol = regionIndex % regionsPerRow;
      const regionRow = Math.floor(regionIndex / regionsPerRow);
      const size = regionSizes[regionIndex];

      // 区域起始位置（居中布局）
      const regionStartX = -totalWidth / 2 + regionCol * (maxWidth + regionGap);
      const regionStartZ = -totalDepth / 2 + regionRow * (maxDepth + regionGap);

      // 区域中心
      const centerX = regionStartX + (size.cols - 1) * hostSpacing / 2;
      const centerZ = regionStartZ + (size.rows - 1) * hostSpacing / 2;

      // 添加区域指示器信息
      groupIndicatorInfo.push({
        centerX,
        centerZ,
        width: size.width,
        depth: size.depth,
        label: region.name
      });

      // 计算每个主机位置
      region.hosts.forEach((host, hostIndex) => {
        const col = hostIndex % hostsPerRow;
        const row = Math.floor(hostIndex / hostsPerRow);

        bars.push({
          position: {
            x: regionStartX + col * hostSpacing,
            y: 0,
            z: regionStartZ + row * hostSpacing
          },
          groupName: region.name,
          height: host.height || barHeight,
          outerColor: host.outerColor || 'normal',
          uuid: host.id,
          layers: host.layers.map(layer => ({
            color: layer.color || 'normal',
            uuid: layer.id
          }))
        });
      });
    });

    return { bars, groupIndicatorInfo };
  }
}

export default GridLayoutCalculator;
```

### 3.4 使用示例

```javascript
// BarChartContainer.jsx
import GridLayoutCalculator from '../utils/LayoutCalculator';

// 后端返回的简化数据
const backendData = {
  regions: [
    {
      id: 'region-1',
      name: '区域 1',
      hosts: [
        { id: 'host-1', layers: [{ id: 'l1', color: 'normal' }] },
        { id: 'host-2', layers: [{ id: 'l2', color: 'warning' }] },
        // ... 更多主机
      ]
    },
    // ... 更多区域
  ]
};

// 使用布局计算器
const calculator = new GridLayoutCalculator({
  hostSpacing: 12,
  regionGap: 300,
  regionsPerRow: 4,
  hostsPerRow: 25
});

const { bars, groupIndicatorInfo } = calculator.calculate(backendData.regions);

// 传递给组件
setBarSceneData({ bars });
setGroupIndicatorInfo(groupIndicatorInfo);
```

## 四、方案对比

| 对比项 | 方案一：后端计算 | 方案二：前端计算 |
|--------|------------------|------------------|
| 后端工作量 | 中等 | 低 |
| 前端工作量 | 低 | 中等 |
| 灵活性 | 高（可实现复杂布局） | 中（网格布局为主） |
| 数据传输量 | 较大（含位置） | 较小 |
| 布局一致性 | 好（后端统一） | 依赖前端版本 |
| 实时调整 | 需要后端支持 | 前端可即时调整 |

## 五、推荐方案

### 5.1 短期（调研阶段）

采用 **方案二：前端网格布局工具**
- 快速验证，无需后端配合
- 布局参数可灵活调整

### 5.2 长期（生产环境）

采用 **方案一：后端计算位置**
- 布局逻辑集中管理
- 支持更复杂的布局策略
- 前端只负责渲染，职责清晰

### 5.3 混合方案

后端提供布局配置，前端计算具体位置：
```javascript
// 后端返回
{
  layoutConfig: { hostSpacing: 12, regionGap: 300, ... },
  regions: [{ id, name, hosts: [...] }]
}

// 前端使用后端配置进行布局计算
const calculator = new GridLayoutCalculator(backendData.layoutConfig);
```
