## 任务说明

按任务步骤快速查看相关文档和代码，先分析需求可行性，并完成调研任务。

## 任务步骤

1. 快速查看README\feature1.md、README\Version2(已完成).md、README\技术可行性分析.md。这分别是前两个版本的迭代说明和上一版本的技术可行性分析（与该次部分需求有重叠）
2. 查看相关代码后查看此文档的需求背景介绍和任务调研，结合上一版本技术可行性分析进一步分析当前最新需求。主要分析基于当前架构是否满足5000个主机的全景展示（这里加上了分区功能）、后期会有双模式切换的功能（将现有模式命名为组件视图、实时模式命名为指标视图）。你需要先分析后期是否支持5000个主机同时转换成指标视图（或两模式来回切换）
3. 分析可行后可开始执行任务调研任务，这里需要注意对区域的创建，可以维持InstancedMesh架构，统一创建区域几何体，这里用到了2D标签显示区域名可以改为平面3D几何体（也可以使用InstancedMesh创建）。或者将标签名以及区域几何体结合在一起（标签名不需要额外创建几何体）
4. 更新README\技术可行性分析.md文档

## 需求背景

自动创建并生成3D动态地图，可全景概览所有监控主机，实时跟踪各主机及运行组件的健康状态；提供灵活的动态过滤功能，能够精准聚焦符合特定条件的监控实体。  区域->主机->服务组件

## 任务调研

- 在用户未选择过滤时需要展示全部服务主机（摄像头拉远可以看到其他主机）。

- 先调研主机数量为5000，每个主机内部服务组件为10时候的场景，观察渲染性能如何？视觉体验如何？

### 调研细节

- 为模拟真实全景场景，需要添加区域（当前被注释）
- 区域代表主机分组，当前可以分为20组，每组分配250个主机
- 初始摄像机角度是俯视查看完整的某一组，后期根据鼠标滚轮滚动可以拉远摄像机看到全景主机。这里需要注意调整摄像机的远角距离
