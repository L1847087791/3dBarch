## 任务需求

1. 结合新业务场景，判断并分析three.js能否满足新业务需求
2. 分析迭代的难点、开发成本、复杂度。

## 业务需求

1. 场景图大致有三个业务属性，集群->主机->服务。对应目前的堆->柱状图外层->柱状图内层
2. 总体上需要两种显示模式（利用控制面板来切换显示），第一种就是目前的一个柱状图内部纵向堆叠内层并撑满。第二种是新需求：点击切换模式按钮后，当前布局不变（即柱状图外层和其位置保持不变），需要变化所有柱状图内层的展示方式----内层和第一种模式的内层意义并不相同了。这时内层数量不会很多（最多5个），且内层不是自动撑满外层的，每个内层需要横向排布（类似于5G信号的那个横向柱状图），并且每个内层高度需要支持实时变化（这代表服务的使用率，高度最高不会超过外层高度，但是一般情况下不会很高）
3. 控制面板在未筛选时展示全部集群及其主机，预计5000个柱状图（主机），但是相应的内层不会太多，最多10个
4. 希望柱状图和场景的样式变得更加好看，需要有运维数字化孪生的特点，可能需要给特定内层一些纹理、文字、边框等等

## 任务难点

1. 第一种模式没什么问题，并且已经测试柱状图数量达到5000，内层10个，拉远摄像机（同时增大far）使得视角能够看到完整的5000个主机。这时InstacedMesh性能依旧优秀，帧率在50以上，首屏加载仍然i保持2s内。
2. 但是对于第二种模式有一些痛难点：1.怎么保证在场景稳定的情况下两种模式互相转换？要丝滑稳定。2.第二种模式下由于内层布局更改，且内层要求实时变化，基于InstancedMesh生成的物体怎么去精准控制？如何保证实时更新的丝滑程度？
3. 对于一些柱状图的细节，比如给内层添加文字、纹理使得更加好看。如果没有使用InstancedMesh则很好办（每个内层单独材质即可）,但是对于多物体绘制则必须使用InstancedMesh来优化，基于此则只能使用Shader编程，但是如果再去引入shader则会大大增加开发成本，这需要深入图形学。
